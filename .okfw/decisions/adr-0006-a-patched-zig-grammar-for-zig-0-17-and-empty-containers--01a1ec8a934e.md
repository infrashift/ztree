# ADR-0006: A patched Zig grammar for Zig 0.17 and empty containers

**Status:** Accepted
**Date:** 2026-11-17
**Source:** [ISSUE-008](/issues/issue-008-zig-0-17-keywords-in-the-zig-grammar--01a1ebfde99b.md). semscope ADR-0010 (semscope commit `f00fb15`).

## Context
tree-sitter-zig v1.1.2 is the last release. It reserves `async`, `await` and `usingnamespace`, and Zig 0.17 removed these keywords. The release grammar also has these limits:
- The clobbers of `asm` accept strings only. Zig 0.15 writes them as a struct literal.
- A `struct`, `enum`, `union` or `opaque` body must hold one member. The parser puts a MISSING `identifier` in each empty body, such as `struct {}`.

The differential step found syntax errors in 71 of 579 files of the Zig 0.17.1 standard library and zmake. Upstream master (2025-09-10) has the same rules.

## Decision
- Keep the release grammar v1.1.2 as the base. Keep `grammar.js` and the patch `zig-0.17.patch` in `third_party/grammars/zig/`.
- Apply the four changes of semscope ADR-0010: remove `async_expression`, `await_expression` and `using_namespace_declaration`, and let `asm_clobbers` read a struct literal.
- Add one change: the four container rules take `optional($._container_members)`.
- Generate `src/` with tree-sitter-cli 0.25.10, the generator of semscope. Without `tree-sitter.json`, the generator writes ABI 14.
- `PIN` records the generator, the command and the SHA-256 of `grammar.js` and `src/parser.c`.

## Consequences
- The standard library and zmake now give syntax errors in 5 of 579 files. The comment count stays at 46,691. ztree and the reference runtime still agree on each file.
- Zig code that uses `async`, `await` or `usingnamespace` as keywords gives parse errors. ztree reads current Zig.
- The Zig grammar stays at ABI 14. It is the only ABI 14 grammar, so the ABI 14 path keeps its tests.
- The new `tree_sitter/parser.h` of the generator declares the ABI 15 struct. The ABI 14 layout probe therefore reads its own copy of the v1.1.2 header in `tests/abi14/parser.h`.
- The grammar of ztree differs from the grammar of semscope by the empty-container change. Without this change, semscope sees a false `container_field` in each empty container. semscope can take the same patch.
- [ISSUE-009](/issues/issue-009-rare-zig-forms-that-the-patched-grammar-cannot-read--01a1ec8ab913.md) records three rare forms that the grammar cannot read.

## Alternatives considered
- **Copy the semscope grammar without a change.** Rejected: 27 of the 32 files that still gave errors had only an empty container.
- **Take upstream master.** Rejected: master keeps the three keywords and the empty-container rule. It also changes the node shapes of calls.
- **Generate with tree-sitter-cli 0.27.2.** Rejected for now: the output of 0.25.10 is the same, byte for byte, as the parser of semscope. That match is a check of the patch.
- **Fix the three rare forms too.** Rejected for now: each needs a change to the type expressions of the grammar, and they occur in 5 files.
